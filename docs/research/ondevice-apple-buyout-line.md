## 一、结论摘要

1. **方向池 ≠ 立项列表。** 同时在架克制。**v1 = D′**（主 iOS/iPadOS，三端可上）。
2. **平台拍板：** T/D′ 三端可上、主 iOS/iPadOS；**S = macOS 独立分发**（实时遮挡）；F 三端收集、主分发 iOS/iPadOS（生日/账单/保修提醒 + 家庭共享）；**R 风水量房并入 HexAstral**。
3. **变现：** 买断 + 家庭共享；D′ 免费短片+水印。
4. **⑥ Mac 归档** 仍降候补。
5. **D′ 风险：** 发热/前台导出。**S 风险：** MAS 沙盒 + 覆盖窗探针。
6. **家庭共享** 主打 F（及 D′/T）；S Mac 偏个人生产力。
7. **P 播客** 可克隆门不立项。
8. **Expo** 不用于 ondevice 买断线；R 进 HexAstral 可走卫星栈。
9. **中国大陆 Gate**；与 HexAstral 抢带宽 —— §六、§七、§十。

## 二、判断标准（筛选器，先于功能清单）

DAMA 类产品能卖断，不是因为「智能」，而是因为**每次使用几乎零边际成本，且用户必须相信图没离开手机**。

1. 痛点高频、做错有后果（泄密、报错、被嘲）
2. Apple 已经把重活做了（Vision / Speech / Translation / Foundation Models / Neural Engine）
3. 你做的是规则、交互、垂直场景，不是自训大模型
4. 不需要账号、云同步、持续推理账单
5. 3 秒内看到「魔法」，免费能用，付费去掉脏东西（水印、张数、批量、导出）
6. **已存在笨拙的 workaround** —— 见下

**核心命题：识别质量由 OS 版本白涨，你养的是规则和交互。**

### 2.1 第 6 条：workaround 测试（需求强度的最佳代理指标）

用户是否**已经在用蹩脚方法**解决这件事？有 = 需求已被证明存在且未被满足，只是解法烂，
可以付费替代。没有，或者 workaround 免费且够用 = 你在创造需求，那是最贵的事。

这条不需要任何调研就能用，而且直接给方向排序：

| 方向 | 现有 workaround | 判读 |
|---|---|---|
| **S 屏幕隐私（①）** | 开专用浏览器 profile、新建访客账户、共享前手动关通知/开专注模式、只共享单个窗口而不敢共享桌面 | **需求已证明，解法很烂** → 可付费 |
| ③ 家庭文件柜 | 建文件夹 + 手动改名 + 日历设提醒 | 笨但存在 → 中等 |
| ⑦ 旅行证件包 | 微信收藏 / 相册专辑 + 出行前翻一遍 | 笨但存在 → 中等 |
| ② 诈骗预检 | 「别点陌生链接」 | 免费且够用 → **不付费** |
| ⑥ Mac 归档 | 不整理，直接用搜索 | 够用 → **不付费** |

**配套做法（比问卷可靠）：** 记一周自己的日志，每次「差点暴露 / 已经暴露」的时刻逐条写下来；
挖现有工具的一星二星差评；翻 r/macapps 与 r/remotework。日志同时是**规则库的第一批来源**。

## 三、2026 新增的三块地基

WWDC26 之后，「Apple 已经把重活做了」的范围明显扩大，直接决定了下面哪些方向今年才成立：

| 新原语 | 内容 | 开出的品类 |
|---|---|---|
| **本机模型有了视觉** | 图片可作为 attachment 进 `LanguageModelSession`（UIImage / CGImage / CVPixelBuffer / URL，任意尺寸；大图更多 token + 延迟）。`OCRTool` / `BarcodeReaderTool` 可作为工具被模型调用 | 语义级预检：从「找模式」升级到「找语境」 |
| **Spotlight 成为本地 RAG 检索工具** | 模型可检索 Spotlight 索引，实现完全本机的个人资料问答 | 个人知识检索类**第一次可以零后端**，此前必须订阅 |
| **PCC 对小开发者免云 API 费** | 首次下载 < 200 万；32k 上下文 + reasoning；像素进 Apple 可验证隔离环境 | 「偶尔一次重活」可进买断产品 |

配套值得利用的：

- **AFM 3 Core**（~3B dense）/ **AFM 3 Core Advanced**（20B 稀疏，激活 1–4B，高端机）
- **Evaluations 框架** —— 能量化提示词/规则迭代后准确率有没有掉。**这就是护城河的载体**，
  竞品靠感觉调提示词，你有回归测试集。
- **macOS 27 `fm` CLI + FoundationModels Python SDK** —— Mac 侧批处理与规则迭代成本骤降
- 框架开源 + utilities 包；模型抽象层（`LanguageModel` protocol、`MLXLanguageModel`）

⚠️ **PCC 只能做锦上添花，不能做主路径**：用户侧有每日额度（iCloud+ 更高），条款可变。
**主路径必须在纯本机可降级跑通。**

⚠️ **对 v1 尤其重要**：实时遮挡的主路径**不是模型**，是确定性 geometry 规则。
视觉模型只在模式切换与手动框选时按需调用 —— 见 §5.7 前提 2。

### 3.5 硬件门槛 API —— 差异化挖掘轴

**核心观察：** 很多 Apple API 在 SDK 里**统一存在**，但运行时 `isSupported` / `isMultiCamSupported` /
`SystemLanguageModel.isAvailable` 等会在旧机型上返回 `false`。这不是 bug，是**天然的设备分层**。

**为什么适合买断线（而非订阅）：**

| 属性 | 含义 |
|---|---|
| 边际成本为零 | 双路采集、本机合成、本机导出 —— 无云账单 |
| 能力随 OS / 芯片白涨 | 你维护的是布局规则、合成管线、热管理策略，不是自训模型 |
| 旧机用户不是目标客户 | 敢买 Pro / 新机的用户 ARPU 更高、更愿为「系统相机做不到的事」付一次性钱 |
| 竞品被迫做全机型兼容 | 你只做 `isSupported == true` 的路径，代码更简单、体验更稳 |

**和「平台 API 不存在」（如 ScreenCaptureKit 仅 macOS）是同一类逻辑：**
切分依据是**系统能力在不在**，不是「用户有没有 iPhone」。

**正确的产品姿势（三种档位，不要二选一）：**

```text
不支持的设备 → 商店页/首次启动写清最低机型；App 内可播演示视频，不假装能用
支持的设备 · 免费 → 完整魔法可体验；导出带水印 / 或时长·布局受限
支持的设备 · 买断 → 去水印 + 全布局 + 批量/快捷指令 + 家庭共享
```

⚠️ **不要**在旧机上硬做「残废版双录」—— 用户会一星差评「骗人」。
**可以**在旧机上只做「单摄 + 看演示」，或根本不装（ASO 写清 `Requires iPhone XS or later`）。

**水印买断为何贴这类场景：** 预览必须完整（否则看不到魔法）；付费去掉的是**导出脏东西** ——
和 DAMA 同构。Dual Cam 导出视频加水印比截图水印更自然，转化理由也更硬。

### 3.6 硬件门槛 API 清单（灵感池原料）

运行时探测，**禁止写死机型列表** —— 只信系统 API。

| 原语 | 探测 API | 大致门槛 | 典型 job | 与 Dual Cam 同构？ |

### 3.7 Dual Camera / 演示录制 —— 能力拆分后的判读

**必须拆开两种完全不同的能力**（此前把它们混在一起否决，不准确）：

| 能力 | API | Web 能不能做 | 判读 |
|---|---|---|---|
| **A. 双物理摄像头**（前后 / 广角+超广）同录 | `AVCaptureMultiCamSession` | 桌面 Chrome 部分可；**iOS Safari 基本做不好两路同时** | 原生有差异，但 **App 已挤满 + Apple 免费 DoubleTake**，买断无杠杆 |
| **B. 脸 + 屏幕/其他 App 界面**同录 | 摄像头 + `ReplayKit` / `ScreenCaptureKit`（或桌面 `getDisplayMedia`） | **有硬局限** —— 见下 | **仍有市场空隙**，且与创作者「录教程」重合 |

#### Web 在 B 上的真实局限（用户纠正，成立）

1. **很多「网页录课」工具只录当前标签页 / 浏览器内**，录不了 Xcode、Figma 桌面端、游戏、系统设置等**浏览器外界面**
2. 桌面 Web 若用 `getDisplayMedia` **可以**选窗口/全屏，但权限摩擦大、画质/系统音不稳定，且 **PiP 脸 + 任意窗口** 的体验远不如原生
3. **iOS Safari 屏幕采集能力弱**：很难稳定做到「前置自拍 + 同时录另一个 App 界面」—— 这正是原生 `ReplayKit` / 广播扩展的地盘
4. 因此：**「Web 已覆盖脸+画面」这个否决理由只对「浏览器内演示」成立，对「演示原生 App / 桌面软件」不成立**

#### A. 双物理摄像头 —— 维持降优先级（不是绝对零市场）

竞品定价（2026-08）：

| App | 定价 | 备注 |
|---|---|---|
| DualFrame | **$4.99 一次性** | 「NO SUBSCRIPTION. EVER.」 |
| DoubleFrame | **$6.99 → $29.99 lifetime** | 兼售周订 |
| DualShot Recorder | **$9.99 一次性** | |
| DoubleTake | **免费** | **Apple 官方** |
| MixCam / 2Cam | 订阅 | 少数派 |

买断是入场券；差异化要卷镜头组合/朝向。**不作为主线**，除非找到极窄垂直 job 且定价能站住 ≥ $9.99。

#### B. 脸 + 屏幕 —— **市场核实（2026-08-29 App Store / 系统能力）**

**先纠正文档里两句说过头的话：**

| 此前写法 | 核实后 |
|---|---|
| 「系统录屏可拉摄像头」 | **iOS 18.3+ 成立**：长按控制中心「屏幕录制」→ 麦克风旁有 **Camera** 按钮 → PiP 前置小窗（[9to5Mac](https://9to5mac.com/2025/01/22/screen-recording-in-ios-is-set-to-improve-thanks-to-three-new-upcoming-features/) / iDownloadBlog / HowToGeek）。**Apple 官方用户指南仍只写麦克风**，文档滞后。HowToGeek 称 **欧盟可能因隐私法未开摄像头叠加**。 |
| 「浮窗方案已商品化」 | **成立，但是小众品类** —— 见下表；不是「红海巨头」，也不是「无人做」。 |

**系统能力边界（即第三方还能卖什么）：**

- 系统 PiP：有，但控件弱（形状/拖拽/触摸指示器/提词器通常没有）
- 系统：任意 App 界面都能录（这点 Web 做不到）
- 系统：不能智能挡通知/敏感区 → **仍是 S 的缺口**

**App Store 实证（iTunes Lookup / 商店页，US，2026-08-29）：**

| App | Bundle / ID | 评分 | 体量 | 变现 |
|---|---|---|---|---|
| **HD Face Cam Screen Recorder**（即 DemoScope，`com.admtal.demoscope`） | [id6755395174](https://apps.apple.com/us/app/hd-face-cam-screen-recorder/id6755395174) | 4.44 | **73 条评分** | 免费全功能 + 10 分钟/水印；站点称 Pro **一次性买断** |
| **FacePiP** | [id6755074920](https://apps.apple.com/us/app/facepip/id6755074920) | 5.0 | **1 条评分** | **$4.99** Unlimited 买断；浮窗 + 系统录屏吃进去 |
| Screen Recorder & Face Video | id6470203742 | 4.13 | 62 条 | 描述偏 **App 内浏览器**，不是任意原生 App |
| 泛「Screen Recorder」大盘（Go Record / Record it! 等） | — | — | **10 万–45 万评分** | 多为游戏录屏/直播，**不是**「脸+任意 App」垂直 |

**读法：**

1. **「脸+屏幕同录」有真实需求** —— 否则 DemoScope / FacePiP 不会上架；你对「系统做不到像样小窗」的怀疑，对 **18.3 之前 / 欧盟 / 要可拖拽形状与触摸点** 的用户仍然成立。
2. **但需求盘子很小** —— 垂直头部约 **几十～一百评分**；对比泛录屏 App 的十万级评分，差三个数量级。
3. **买断已有人用**（FacePiP $4.99、DemoScope 宣称 lifetime）—— 符合创作者工具定价，但 **不证明值得你占审核名额**。
4. **再做一个「也能叠脸」的录屏 App = 与系统 18.3+ 和 DemoScope 抢同一窄缝**；差异化只能落在：触摸指示器、提词器、**录屏隐私遮挡（S）**、导出模板 —— 不能落在「能不能叠摄像头」。

**执行结论（更新）：**

| 项 | 结论 |
|---|---|
| A 双物理摄像头 | **不进主线** |
| B 纯「脸+屏合成录制」作独立 App | **不立项**（系统 18.3+ 已有基础能力 + 小众竞品已占位；评分体量证明市场窄） |
| S 录屏隐私 | **主线保留 · 仅 macOS 做实时挡**；iOS/iPad 做截图预检（见下） |
| 若未来做创作者录屏 | 不要承诺「iOS 录屏时智能挡」—— **做不到**；隐私能力挂靠 S 的平台分工 |

**为何「录的时候智能挡」只能是 macOS（与 S 产品定义一致）：**

| 平台 | 实时遮挡（录屏/共享进行中） | 截图/成片发前预检 |
|---|---|---|
| **macOS** | **能** —— `ScreenCaptureKit` 取帧 + AppKit 覆盖窗口盖在通知/chrome 上；或排除窗口 | 也能，但非主路径 |
| **iOS / iPadOS** | **基本不能** —— 无系统级覆盖窗口；无法在别的 App / 通知横幅之上画遮罩；系统录屏管线第三方插不进「先挡再编码」；Broadcast Extension 只服务**你自己的**推流目的地，挡不了用户用控制中心录到相册的那条路径 | **能** —— 用户把图/片丢进分享 sheet，在你 App 内 checklist + 打码后导出 |

因此 S 的不对等分工不是妥协，是 API 边界：

- **v1 = macOS 实时遮挡**（共享屏幕 / 录屏时的安全演示模式）
- **v2 = iOS 截图预检**（发出去之前的静态预检）—— 不是「手机版实时遮挡」

DemoScope / FacePiP / 系统录屏都不做智能挡泄密 → 缺口在 **Mac 实时**；不要误写成「iOS 录屏隐私 App」。

### 3.8 成本依据套利 —— 买断 + 家庭共享的真正攻击面

**这是比「硬件门」更强的一条轴。** 硬件门只决定你服务谁；
**成本依据**决定你能不能把在位者的定价模式打掉。

**订阅只有三个正当理由：**

1. 持续的**云推理 / 存储**成本
2. 持续的**内容 / 数据**更新
3. **多端协作**与团队席位

**关键判据：当 Apple 把能力搬到端侧、且模型随 OS 白送，第 1 条就消失了。**
若品类里的在位者仍在按第 1 条定价，就出现套利窗口 —— 你用**买断 + 家庭共享**打掉它的定价基础。

**反向推论（Dual Cam 的教训）：若在位者本来就没有云成本，买断不是武器，只是入场券。**
双摄录制从第一天就是纯本机的，所以买断早已是常态、价格已崩到 $4.99（§3.7）。
**必须去找「在位者真的在烧云账单」的品类。**

#### 2026 最大的一次成本依据崩塌：SpeechAnalyzer

iOS 26 / macOS 26 的 `SpeechAnalyzer` + `SpeechTranscriber` 把语音转写彻底端侧化：

| 特性 | 旧 `SFSpeechRecognizer` | **`SpeechAnalyzer`（iOS 26+）** |
|---|---|---|
| 处理位置 | 多数语言**上传 Apple 服务器** | **纯端侧，音频不出机** |
| 时长上限 | ~1 分钟/请求 | **无上限**（可一次转 90 分钟讲座） |
| 速率上限 | 1000 请求/设备/小时 | **无** |
| 模型分发 | — | **随 OS 出厂，App 不用打包权重** |
| 精度 / 速度 | — | 独立评测 WER 2.12%（Whisper Small 3.74%），比 Whisper large-v3 turbo **快约 2–3 倍** |

**这三件事同时成立，才构成套利窗口：**

- 音频**不出设备** → 隐私叙事成立（律师、医生、HR、记者、投资人）
- 模型**不用打包** → 你的 App 几 MB，而 MacWhisper 类要下载 GB 级 Whisper 权重
- **无时长/速率上限** → 「无限时长」可以写进商店文案，而云竞品必须按分钟收费

#### 攻击面对照（真实竞品定价，2026-08）

| 品类 | 在位者 | 年成本 | 云成本依据 | 端侧替代 | 买断攻击力 |
|---|---|---|---|---|---|
| **会议 / 讲座转写** | Otter.ai | **$99.96/yr**（纯云、无买断档） | **已消失** | SpeechAnalyzer + AFM 摘要 | **强** |
| **短视频字幕烧制** | Captions.ai $9.99–69.99/mo · Submagic $12–23/mo · Descript $16–24/mo | **$120–840/yr** | **已消失** | SpeechAnalyzer + 文本渲染 | **强**（但有设计跑步机） |
| 端侧转写（Mac） | MacWhisper $69 lifetime · Aiko ~$24 | 已是买断 | 无 | — | 弱（买断已常态，但**你有 OS 模型优势**） |
| 双摄录制 | DualFrame $4.99 · DoubleFrame $29.99 | 已是买断 | 无 | — | **弱**（§3.7） |

⚠️ **MacWhisper / Aiko 已证明买断在转写品类可行**（$24–69 一次性，活得很好）。
它们的弱点正是你的机会：**要打包 Whisper 权重**（下载大、启动慢、iOS 上只能用 medium/small）。
用 `SpeechAnalyzer` 你的包体几 MB、精度更高、速度更快 —— 但**代价是只能服务 iOS 26+ / macOS 26+**，
这正是 §3.5 的硬件门逻辑：**放弃旧机，换更简单的代码和更好的体验。**

#### 家庭共享在这里是杀手级论据

买断 + 家庭共享对上纯云订阅，成本对比是**碾压级**，可以直接写进 ASO：

| 场景 | Otter.ai | 你（买断 $39 + 家庭 6 人） |
|---|---|---|
| 1 人 · 第 1 年 | $100 | **$39** |
| 4 人家庭 · 第 1 年 | $400 | **$39** |
| 4 人家庭 · 第 3 年 | **$1,200** | **$39** |

**为什么竞品结构上跟不了：** 云推理产品每个家庭成员都在烧它的推理账单，
所以要么不开家庭共享，要么按席位加价。**本机推理边际成本为零，这是你独有的杠杆**（§5.5）。

已有小玩家（如 CaptionEdge，$0.99/mo）已经把「Family Sharing 最多 6 人」当作 Pro 档卖点 ——
说明这条论据在市场上已被验证有效，但还没人把它和**一次性买断**组合起来打。

#### 结构性发现：转写与屏幕隐私是同一群人

| | S 屏幕隐私（macOS） | T 端侧转写 |
|---|---|---|
| 用户 | 远程工作者、开会/演示的人 | **同一批人** |
| 承诺 | 画面不出设备 | 音频不出设备 |
| 场景 | 共享屏幕的那一刻 | 同一场会议的录音 |
| ASO 叙事 | 「别让屏幕出卖你」 | 「别让录音出卖你」 |

**这意味着 T 与 S 复用营销带宽，而 Dual Cam 会撕裂它**（§10.3 带宽是稀缺资源）：
Dual Cam 的用户是内容创作者，与远程工作者几乎不重叠，等于要讲第二个故事。

**推荐的第二条线因此是 T（端侧转写），而不是 D（Dual Cam）。**
仍需通过你自己的 workaround 测试（§2.1）：你开会时是否已经在用蹩脚方法记录/回顾。

### 4.2 逐项展开

**S 屏幕隐私 —— v1 立项（① Mac 实时端 + ⑤ iOS 截图端）**

同一个 job：**别让屏幕出卖你**。

*v1 = macOS 实时遮挡（完整范围）*

自动遮挡系统通知横幅、浏览器书签栏与标签标题、邮件/IM 预览列表、桌面文件名、
终端里的密钥形状串、日历中的客户名。一键进入「安全演示模式」，退出即恢复。

- **买断成立**：零边际成本；识别质量随 macOS 白涨；你维护的是「哪些区域该盖」的规则库
- **护城河真实**：ScreenCaptureKit + 覆盖窗口 + TCC 权限链 + 逐 App 区域规则 + Evaluations 回归集，
  抄袭成本高。这与「② 没有护城河」正好互补
- **痛点贵**：泄密对象是公司与客户，付费意愿是 B2B 量级；泄密过一次的人会立刻付钱
- **workaround 已存在且很烂**（§2.1）—— 需求无需验证，只需替代
- **可演示性最强**：屏幕录制产品的演示媒介就是屏幕录制，天然自带素材
- **AI 依赖度低**：主路径是确定性 geometry 规则，Apple Intelligence 不可用也能工作 —— 比 ⑤ 更稳
- **绕开中国区 Gate**：Mac 生产力工具全球市场（美/日/欧）足够

⚠️ 工程量比 DAMA 大一档，**这正是壁垒，也正是风险** —— 见 §5.7。

*v2 = iOS / iPadOS 截图预检（原 ⑤ 窄切片）*

旧做法正则找手机号身份证；新做法让模型先理解截图属于什么场景，再按场景清单检查：
IM 群聊 → 群名/昵称/头像/引用消息；工作台 → Jira 列名/客户名/内部域名/工牌。
**产品是那份「你漏了什么」的清单，不是绿色方块。**

- 入口：iOS 分享 sheet / 相册选图（不进 Photos 全库扫描）
- 场景：先只做 IM 聊天截图 + 工作台/桌面截图两类
- 不做：视频 / Live Photo、全相册批量、CloudKit 同步
- 演示句：「公司名和工牌还在 → 一键盖掉再发」

**为何是 v2 而不是 v1**：iOS 侧竞争密度高（含 DAMA 本身）、ARPU 低、护城河浅。
先用 Mac 端建立规则库与 Evaluations 资产，再把它降维到 iOS，是顺序正确的方向。

---

**② 诈骗话术本机预检 —— 可走「熊猫吃短信」路线，但仍不建议作 v1**

**正确姿态（用户补充，成立）：** 对电话转写稿 / 短信 / 粘贴文本 / 聊天截图做**本机**分析；
全程说「疑似 / 警告 / 常见话术特征」，**绝不说「这是诈骗」**；子女买给父母 + 家庭共享仍是强转化。

对标 **熊猫吃短信**：Message Filter / 本地模型、不上传内容、语义分类而非关键词——已验证「本机 + 隐私」在中文区能卖。
差异是熊猫做**拦截分类**（系统扩展位清晰）；诈骗预检做**主动粘贴/导入分析**（分发位弱一档，但来源可更广）。

**仍不独立作 v1 的理由（收窄后）：**

1. **演示弱于 S**：可演示「粘贴一段 → 列出三条疑似特征」，但弱于「盖住泄密」的正面魔法
2. **护城河仍偏内容**：规则/话术骨架要养；可用 AFM 降对词库的依赖，但不能假装零维护
3. **Guideline 1.4 / AUR**：软表述降低风险，不消除；漏判差评杀伤力仍大
4. **首发若非大陆**：杀猪盘语境与 ASO 不匹配（§七）

**若立项：** 独立小 App 或 S 的「防骗模式」；入口 = 粘贴 + 分享 sheet 图片 OCR +（可选）通话录音转写后再检；
输出 = 特征清单 + 「建议核实官方渠道」；买断 + **家庭共享主打子女给父母**。

**③ / F 家庭文件柜 —— 「保修到几号」+ 提醒 + 家庭共享（成立 · v1 并列候选）**

**2026-08-30 拍板：方向成立，值得做。** 卖点不是「本地 RAG / 第二个 Spotlight」，而是：
拍照进柜 → 抽出到期日 → 系统提醒 → **家庭共享同柜**。

⚠️ **纠正常见误解：** `SpotlightSearchTool` / Core Spotlight **不是 Mac 独有**（iOS / iPadOS / macOS / visionOS 都有）。
但产品形态要分清：

| | 家庭文件柜该做的 | Raycast / 系统 Spotlight 已做的 |
|---|---|---|
| 索引范围 | **你导入的保单/租约/保修卡**（App 捐赠到 Core Spotlight） | 全盘文件、扩展、快捷启动 |
| 用户问题 | 「空调保修到几号」 | 「打开某某 App / 搜某个文件名」 |
| 家庭共享 | **第一天主叙事** | 启动器无此杠杆 |

若做成「Mac 上第二个 Spotlight」，必输 Raycast。只有做成 **窄单据库 + 到期日 + 家庭共享** 才有缝。
go/no-go：**中英保修卡到期日抽取评测**。失败形态 =「搜不准的智能文件柜」→ 砍开放问答、保提醒+结构化字段。

**D′ 发前隐私（可立项：视频导出打码 + 图片打码）**

对 DAMA 硬差在视频。工程：降采样检测 + 跟踪；长导出以前台为主，不承诺锁屏后台跑完。细节与发热策略见 [ondevice-app-todo.md](./ondevice-app-todo.md) §2.4。

**R LiDAR 量房（业务驱动）**

仅 `RoomCaptureSession.isSupported`。交付绑定自装修尺寸图、风水规则叠加（娱乐/文化表述）、或报价出图 —— 禁止 RoomPlan Sample 壳。见 todo §2.6。

**P 自动化播客（边界）**

本机 TTS → 音频文件：**能**。固定 Podcast RSS：**必须托管**（用户自备 R2/Buzzsprout 或你养瘦后端）。声音克隆 / Personal Voice 当播客素材：**不做**（AAC 定位、非商业、不可 capture）。见 todo §2.7。

**④ 面单 / 票据：脱敏和抽取一起卖（第二款候补）**

在**卖家**人群身上这是同一个动作：快递面单同时含姓名电话地址，既要抽取（对账、发货记录）
又要脱敏（发群里、贴评价）。一次拍照两个输出。同理是报销：财务数据不能上云是硬约束。
2026 加成是 `OCRTool` 可被模型调用，模型能在「读文字」和「理解版式」间往返。

**⑥ Mac AI 归档整理 —— 降为候补（过不了 §二）**

下载夹 / 截图夹 / 扫描件堆山：本机模型看内容 → 重命名 + 归类 + 打标签。
`fm` CLI 让高级用户可脚本化。Mac 用户对 ¥68–128 一次性付费习以为常。

**逐条对照 §二 筛选器：**

| 筛选器 | S 屏幕隐私 | ⑥ Mac 归档 |
|---|---|---|
| 1 痛点高频、做错有后果 | 强（泄密是真事故） | **弱**（归档错了撤销即可，无后果） |
| 2 Apple 做了重活 | 是 | 是 |
| 3 你做规则、交互、垂直 | 是（区域规则库） | **Hazel 用 15 年占了规则位**；2026 AI 文件整理是拥挤赛道 |
| 4 无账号无账单 | 是 | 是 |
| 5 3 秒看到魔法 | 是（一键进安全模式） | **不是**（批量、后台、慢） |
| 6 已存在笨拙 workaround | **是且很烂** | 「不整理直接搜」够用 → 不付费 |

**更要紧的是：⑥ 正好是 §10.1 定义的「一般化的效率工具 + AI」** —— 没有分发位、
没有信任结构、垂直规则被现有玩家占据。它是本文档自己判定为「真正死掉的那类」，
只因挂了 AI 才看起来还行。**除非第 1、5、6 条的判读改变，否则不做。**

**⑦ 旅行证件包（第二款候补）**

护照、签证、机票、酒店确认函本机结构化，出行前提醒有效期（护照剩余六个月规则、签证到期），

## 五、架构决策

### 5.1 多个独立 App，但不是同时上架

**长期**几个通用方向应是几个独立 App（各自 ASO、各自通用购买），不是合并成一个多功能 App。
DAMA 的逻辑是窄即可卖：ASO 按场景定位，合并会同时毁掉定位和转化。

**但 ①⑤ 合并是例外且正确的**：§5.1 禁止的是合并两个**不同 job**；①⑤ 是同一 job
（别让屏幕出卖你）的两个 surface。判据是「用户会不会用同一句话描述它」——
「防止屏幕泄密」能同时覆盖两端，「打码」和「归档」不能。

**执行上：** 同一账号**同时在架的端侧 App ≤ 1（v1）→ ≤ 2（渠道验证后）**。
S 加 iOS 端属于同一 App 加平台，不占名额。

⚠️ **风险联动**：[market-landscape-hexastral.md](./market-landscape-hexastral.md) §结论 4 已记录
Apple 2026-06 起收紧低质量 / 低互动 app 规则，**多 App 矩阵易触发「app 家族 / 设计 spam」**。
本线与 HexAstral 同属一个开发者账号，同样受这条约束。

### 5.2 共享引擎：从 v1 长出，不是先建空包

跨端复用的不是 UI，是引擎。将来建一个本地 SPM 包（暂名 `OnDeviceKit`）承载：

- 模型可用性探测 + **逐设备降级策略**（不是逐 OS —— 见 §5.3）
- Vision / OCR / 条码封装
- **区域与场景规则引擎** + 严重度分级
- **Evaluations 回归测试集**（核心资产）
- 打码渲染、EXIF 剥离、导出

角色等同于 Expo 线的 `@zhop/*`。

**抽包时机：** 代码先写在 Mac target 里；**S 加 iOS 端（阶段 3）时再抽成 SPM**。
这个时机比上一版更自然 —— 同一产品跨端复用面大，规则引擎与 Evaluations 可直接复用，
不像 ⑤→④ 那样要先猜哪些能共享。

### 5.3 降级要按设备，不按操作系统

Apple Intelligence 硬件门槛三端不一致（iPhone 15 Pro+ / iPad M1+ / Mac Apple Silicon），
且用户可在设置里关闭、模型可能仍在下载。必须**逐设备探测 + 降级**（退回 Vision 传统 CV 能力），
而不是假设「macOS 就有」。对 v1 尤其重要：**遮挡的主路径本来就该是确定性规则**（§5.7 前提 2），
模型只是增强层，所以降级路径不是补丁，是默认路径。

### 5.4 跨设备同步：不在 v1，也不在 v2

**长期：** 同一 Apple ID 跨端是通用购买的卖点；若需要，用 CloudKit 私有数据库
（消耗用户自己的 iCloud 配额），对外话术仍成立：数据不进我们的服务器。

**v1（Mac 实时遮挡）：** 帧只在内存，不落盘、不出机，**没有可同步的数据**。
唯一值得同步的是**用户自定义规则集** —— 用 iCloud Key-Value 或导出 JSON 即可，不需要 CloudKit。

**v2（加 iOS 截图预检）：** 仍不建资料库，截图处理完即导出。
CloudKit 留给 ③ / ⑦ 等真有「跨设备文档库」需求的方向。

### 5.5 家庭共享 —— 与买断制天然一组，但在 Mac 优先下要到 v2 才兑现

**结构上的关键点：本机推理的边际成本为零，所以「一次购买、全家 6 人可用」对我方零成本。**
订阅制 / 云推理竞品做不到这件事 —— 每个家庭成员都会烧他们的推理账单，
所以他们要么不开家庭共享，要么按席位加价。这是买断 + 端侧组合独有的杠杆。

**实施：**

- 付费 App 与**非消耗型 IAP** 均可在 App Store Connect 中**逐产品**开启家庭共享，
  覆盖组织者 + 最多 5 名成员
- 与通用购买叠加后的卖点是乘法：**6 人 × 3 平台，一次买断**
- StoreKit 2 侧需正确处理 `Transaction.ownershipType == .familyShared`
  —— 不要把家庭共享的交易误判为异常或盗版；同时处理 `revocationDate`
  （家庭组变动 / 退款会撤销权益）
- ⚠️ 一旦开启，关闭不会回收已获得权益的成员 —— **视为不可逆决策**

**各方向的家庭共享价值不均：**

| 方向 | 家庭共享价值 | 说明 |
|---|---|---|
| **T 端侧转写** | **极高** | **对上 Otter $100/yr/人 是碾压级论据**（§3.8）：学生家庭、夫妻同为知识工作者、给父母转写就诊录音 |
| ② 诈骗预检 | **极高** | 子女买给父母就是核心场景 —— 但已否决为独立 App |
| ③ 家庭文件柜 | **极高** | 保单 / 租约 / 保修卡本就是家庭级资产 |
| ⑦ 旅行证件包 | 高 | 全家出行，同行人证件到期提醒 |
| S iOS 端（v2） | 中 | 「教家人怎么发安全截图」可讲 |
| **S Mac 端（v1）** | **低** | 工作场景、个人使用 |
| ④ 面单 / 票据 | 低 | 偏个体经营 |
| ⑥ Mac 归档 | 低 | 工作场景，个人 |

⚠️ **诚实记录 Mac 优先的一个真实代价：家庭共享杠杆在 v1 基本用不上。**
它最强的三个方向（②③⑦）全排在后面。v1 仍应开启（零成本 + ASO 信任信号），
但**不要把它当 v1 的转化主张写进商店文案** —— 那是 v2 接上 iOS 端之后的事。

**必须澄清的边界：家庭共享的是「购买权」，不是「数据」。**
方向 ③ 若要让家人**互相看到文档**，那是 CloudKit **共享数据库（CKShare）**，而不是私有库。
默认应为各自独立的私有库，共享文档作为显式的、按条目授权的可选功能。
混淆这两者会同时造成隐私事故和差评。

### 5.6 定价

**v1 首发市场：** 美 / 日 / 欧 / 港台（§七 门控下不含中国大陆）。ASO 与演示内容按
**远程会议 / 直播 / 录课 / 客户演示泄密**写（通知弹窗、书签栏、终端密钥），不用中文杀猪盘语境。

| 层 | v1（macOS · USD） | 大陆上线后（CNY 参考） |
|---|---|---|
| **免费** | 安全模式可用，但**只盖系统通知横幅** —— 最痛的单点，本身就是演示 | 同左 |
| **买断 v1（macOS）** | **$19.99**（区间 $14.99–24.99）· 解锁浏览器/终端/桌面/日历遮挡 + 自定义区域规则 + 规则导入导出 | ¥68–128 |
| **v2 通用购买（+iOS/iPad）** | 同一 bundle，**v1 老用户免费获得**；新用户价格上调一档（$24.99–29.99） | ¥98–158 |
| 第二款（③/④/⑦） | 独立 App，按各自场景定价 | — |

**免费档设计是关键**：免费只盖系统通知 —— 它解决了最高频的尴尬（会议中弹出客户名），
所以用户会真的用；而其余遮挡目标（书签栏、终端、桌面）才是付费理由。
这样免费档不是阉割版，是**长期驻留的演示**。

**「老用户免费拿 iOS 端」是刻意的口碑杠杆**：通用购买让一次购买覆盖三端，
这句话在 Mac 买断市场是强卖点，而对我方零成本。

**不要按次数 / 时长计费。** 端侧产品一按量，用户会觉得被骗 —— 帧明明没上传。

**关于摊薄的权衡：** 家庭共享理论上会减少购买份数。对零边际成本、靠口碑扩散的窄工具，
转化率与口碑收益仍判定为净增。

### 5.7 技能栈风险（v1 最大的单点风险）

现有栈是 Expo / TypeScript / Cloudflare，**没有出货过原生 macOS App**。
① 的完整范围需要一次性掌握：

| 能力 | 陌生度 | 备注 |
|---|---|---|
| Swift + SwiftUI | 中 | 语言本身不难，但 SwiftUI 在 macOS 上的坑远多于 iOS |
| **AppKit 覆盖窗口** | **高** | `NSWindow` 层级与 window level、忽略鼠标事件、多显示器、Space 切换 |
| **ScreenCaptureKit** | **高** | 帧流处理、`SCContentFilter`、实时性能预算 |
| TCC 权限链 | 中 | 屏幕录制权限的授权/撤销/引导，被拒后的降级路径 |
| 公证与分发 | 中 | Developer ID 签名 + notarize（若走独立分发）；MAS 沙盒限制需先验证 |
| Foundation Models 视觉 | 中 | 与 iOS 一致，但实时路径上很可能用不起 —— 见前提 2 |

⚠️ **写任何产品代码之前必须验证的两个前提（go/no-go 级）：**

**前提 1 —— MAS 沙盒是否允许所需的「屏幕录制 + 覆盖窗口」组合。**
若不允许，只能走 Developer ID 独立分发；那会同时失去 App Store 分发位、家庭共享和通用购买
—— §5.5、§5.6 的整个商业模型要重写。**这是本方向唯一的生死前提。**
探针失败时不要直接转独立分发，先停下重评。

**前提 2 —— 实时路径的算力预算。**
60fps 下不可能每帧跑视觉模型。真实做法必须是分层：

- **实时层（每帧）**：确定性 geometry —— 通知横幅位置、窗口 chrome、书签栏区域、
  已知 App 的固定 UI 坐标。零模型调用
- **按需层（模式切换 / 手动框选 / 窗口变化）**：Vision + AFM 视觉做一次扫描，产出「这块该盖」的建议
- 若方案假设「模型逐帧看画面」，方案不成立

这两条决定了 v1 是 **3 个月还是 6 个月**。**阶段 0 的第一件事是做这两个探针，不是搭工程骨架。**

## 六、Expo 与原生的关系（明确结论）

**Expo 仍然必要，但这条线不能用 Expo 做。**

| | HexAstral 线（Expo） | 端侧买断线（原生 Swift） |
|---|---|---|
| 为什么必须 | Android/Play、9 语言、`@zhop/*`、Web、EAS、RevenueCat、已有 6 个 app | **ScreenCaptureKit、AppKit 覆盖窗口**、图像 attachment、Spotlight 工具、guided generation 均无可靠 RN 封装 |
| 后端 | Cloudflare Workers + D1 | **v1/v2 无后端**；文档库方向可用 CloudKit 私有库 |
| 变现 | 订阅 + 消耗品（RevenueCat） | 一次性买断（通用购买 + 家庭共享） |
| 工具链 | bun / turbo / biome / EAS | Xcode / SPM / swift-format / notarize |

**不要放进同一个 monorepo。** 工具链正面冲突（`bun install` vs SPM、biome vs swift-format、
EAS vs Xcode 公证），发布节奏也完全不同。用独立仓库。

**唯一合理的交叉点**：HexAstral 将来若想用 Foundation Models 做本机小任务
（例如 Yuun 的本机摘要），可以写一个 Expo native module 引入。那是叶子能力，
不改变主栈，也不构成合并两条线的理由。

## 八、Apple AUR 红线（先于功能设计）

[Foundation Models Acceptable Use](https://developer.apple.com/apple-intelligence/acceptable-use-requirements-for-the-foundation-models-framework/) 明确禁止：

- **基于生物特征数据对个人分类以推断敏感属性**
- 在**就业、医疗、法律**等高风险领域，产出无人监督且对个人权利有实质影响的结论

因此以下**不是能不能做好的问题，是能不能用这套框架做的问题**：简历评价 / 面试打分 /
体检单给建议 / 合同给法律意见。

**可行变形恒为「定位 + 清单 + 提示」，不为「判断 + 建议」。**
触发 `guardrailViolation` / `GenerationError.refusal` 时必须有优雅降级；
用越狱提示词绕过守卫本身违反 AUR。

**对 v1 的实际影响很小**：遮挡是「定位 + 覆盖」，不产出关于人的判断。
这也是 Mac 优先在合规上比 ② 更干净的原因之一。

（同一条 AUR 也是 Syel 端侧化评估的主要否决项 —— 见 [decisions/0028](../decisions/0028-face-oracle-dual-track.md) §5。）

- 要跟最新大模型比质量（写作、绘画、开放域问答）

## 十、获客假设与两条线的资源冲突

### 10.1 护城河不能是「我们有 AI」

AI 确实抬高了用户阈值，但更准确的说法是：**「通用能力」贬值了，「最后一公里的贴合」升值了。**
DAMA 能卖，不是因为它有 AI —— 前沿模型的识图能力远超它。是因为前沿模型结构上做不到三件事：

1. **占不住分发位**：ChatGPT 进不了分享 sheet，更进不了你共享屏幕的那一刻
2. **满足不了信任条件**：它必须上传，而这个场景的前提是「画面没离开设备」
3. **不懂垂直语境**：它不知道在中文职场里工号、群名、未读数是敏感的

**推论：任何以「我们接了大模型」为卖点的功能都会输**，因为前沿模型永远更强更便宜。
差异化必须落在**分发位、信任结构、垂直规则**上 —— 这与 §二 第 3 条同义。

S 在这三条上都很强：分发位是「共享屏幕的那一秒」（前沿模型结构上到不了）、
信任结构是「帧不出设备」、垂直规则是「哪些区域该盖」的规则库。

也不必接受「不带 AI 就没价值」的强版本。2026 仍然活得好的非 AI 产品有三类：
极窄的确定性工具（计时 / 记账 / 传输）、内容或数据护城河、网络效应产品。
**真正死掉的是「一般化的效率工具」** —— 没有数据、没有网络效应、没有分发位的美化壳。
判断轴不是有没有 AI，而是**有没有 AI 拿不走的东西**。（⑥ 就是被这条否掉的 —— §4.2 ⑥。）

对照 HexAstral：它的护城河**不是** AI（LLM 是 Kimi / Gemini / Qwen 商品化产能），
而是 `astro-core` 的确定性排盘引擎 + 文化语料 + 4–9 语言本地化 + ADR-0003 合规口径。
AI 在那条线上是**渲染器**，不是护城河。

### 10.2 渠道已变：从 SEO / 投放转向创作者第一人称叙事

传统链路（「XX 怎么做」博文 → 落地页 → 下载）因为 AI 摘要与对话式检索吃掉了
informational query 的点击而断链；投放侧注意力迁移导致 CAC 波动加大。
接替它的是**「我遇到了这个问题 → 我这样解决」的第一人称内容**。

但要看清这条渠道的性质：**它是创始人时间的支出，不是营销预算的支出。**
不能加预算放量，依赖本人可信度与持续输出。对独立开发者是优势（痛点故事本来就是真的）。

**关键不对称 —— 可演示性：**

| | 端侧买断线（S） | HexAstral 线 |
|---|---|---|
| 痛点能否 15 秒演示 | **能，而且演示媒介就是产品本身**。录一段「共享屏幕时通知弹出客户名 → 一键进安全模式」 | **不能**。八字排盘的价值无法在 15 秒内自证 |
| 痛点性质 | 「我刚才差点泄密」—— 具体、当下、有后果 | 「我想知道我是谁」—— 抽象、长期、无紧迫性 |
| 适配打法 | **演示驱动**：短视频 / 屏录 | **内容驱动**：节气 / 命理知识本身有价值，App 作承载（媒体打法，周期长） |

所以不是「两条线都用同一套新渠道」。端侧线天然适配演示驱动；HexAstral 只能走内容驱动
—— 而 Yuun 的文化库（二十四节气深读、宜忌词条）其实已经是这类内容资产，
应当被当作**获客资产**而非 App 内附属功能来经营。

### 10.3 真正的冲突不是质量，是共享的稀缺资源

「营销与产品质量都要提高」方向正确但不可执行。可执行的诊断是：
**营销带宽与审核信用额度是两条线共享且有限的资源。**

- **营销带宽**：在创作者叙事渠道里，一个人只能可信地讲 1–2 个故事。
  现有 6 个 App × 4–9 语言已经把带宽摊到不可能
- **审核信用**：[market-landscape-hexastral.md](./market-landscape-hexastral.md) §结论 4 记录的
  「app 家族 / 设计 spam」风险按**开发者账号**累计，两条线共担（另见 §5.1）

**因此本线的推进必须以 HexAstral 收敛为硬前置，而不是并行加码：**

1. 完成 §10.4 **HexAstral 停损清单**（未完成则不开 Xcode 项目）
2. 端侧线**只立项 S 的 Mac 端** —— 验证「演示驱动获客是否成立」，不只是「产品能不能做出来」
3. 渠道假设未验证前不铺第二个 App。铺开的成本不在开发，在带宽与审核额度

⚠️ **Mac 优先额外增加了一项时间冲突**：§5.7 的技能栈学习曲线是 3–6 个月的**深度专注**，
比原计划的 iOS 4–6 周更难与 HexAstral 的发布节奏并存。停损清单因此更重要，不是更次要。

### 10.4 HexAstral 停损清单（端侧线开工前置）

端侧 v1 的第一项不是 Swift 代码，是下面清单**全部勾选**。否则两条线会在同一日历里互抢。

| # | 动作 | 目标 |
|---|---|---|
| H1 | **叙事主力 ≤ 2 个** | Yuun（节气/黄历内容资产 · 媒体打法）+ Yuel（情感话题）继续；其余明确「维护不扩 ASO」 |
| H2 | **过审节奏冻结新 App** | Yuun / Yuel 当前提审窗口内，**不**在同一账号新增端侧 App 提审 |
| H3 | **维护模式** | Feng · CoinCast · Lantai · Syel：不新开 locale、不新开商店截图矩阵、不占创始人演示叙事 |

Syel / 大陆 / Android Play 等仍按各自 launch doc 走；本清单只解决**带宽与审核**冲突。

- [ ] 分层实现：确定性 geometry 跑实时；Vision + AFM 视觉按需（§5.7 前提 2）
- [ ] Apple Intelligence 不可用时降级路径**必须可演示**（它本来就是默认路径 —— §5.3）
- [ ] 多显示器 / Space 切换 / 全屏 App 的正确性
- [ ] TCC 权限被拒时的引导与降级
- [ ] App Store 隐私标签：**不收集**（帧不出设备、不落盘）
- [ ] 家庭共享开启（零成本），但**不作为商店文案主张**（§5.5）

**内部里程碑（非发布门控）：第 2 周末做到「自己开会天天开」。**
只盖系统通知也算达标。做不到就说明遮挡目标选错了 —— 先改目标，再往下写代码。

### 阶段 2 — 渠道验证（上架后 4–6 周）

验证对象**不是**功能清单，是 §10.2 的演示驱动获客假设：

| 信号 | 通过线（可调） |
|---|---|
| 自然下载 | 无付费投放下，屏录演示视频 / 帖子带来首批安装 |
| 免费→买断转化 | ≥ 自己设的底线（Mac 工具类可设 3–5%，高于 iOS） |
| 免费档留存 | 用户真的把「只盖通知」的免费档留在菜单栏（这是付费的前提） |
| 拒审 / 差评 | 无 Guideline 1.4 安全宣称拒审；无「该盖没盖导致泄密」类一星潮 |

**未通过：** 收窄遮挡目标或改演示，**不**接 iOS 端，**不**开第二款 App。

### 阶段 3 — v2：接上 iOS / iPadOS 端（仅当阶段 2 通过）

1. 从 Mac 端抽 `OnDeviceKit`（Vision / 区域规则 / 打码渲染 / Evaluations）—— §5.2
2. 同一 bundle 加 iOS target → 通用购买；**v1 老用户免费获得**（口碑杠杆 §5.6）
3. iOS 端形态 = ⑤ 窄切片：分享 sheet → 场景分类 → checklist → 一键盖
4. ② 作为「聊天截图」场景内的一条检测规则并入（清单语气，非判决）
5. 家庭共享的价值在此刻才真正上线，可进商店文案

### 阶段 4 — 第二款（有余力）

③ 家庭文件柜 / ④ 面单票据 / ⑦ 旅行证件包 中选一，共用 `OnDeviceKit`，仍只 +1 个在架 App。
**⑥ 除非 §二 第 1、5、6 条的判读改变，否则不做。**

### 持续

- 中国区：§七 G1–G3 每季度复检，不预先投入（Mac 优先下已从阻塞项降为纯增量）
- 需求日志持续记录 —— 它是规则库的来源，也是演示内容的来源
- 灵感池其余方向：不进提审队列，除非阶段 2 已通过且 S 双端已 ship
