# Lantai — 同意 / TOS / 视觉模板：可行性备忘录

> 2026-08-19 · 内部产品法律研究，供 UseONE, LLC 交给**执业律师**改 TOS / 隐私政策 / 勾选文案。
> **本文不是法律意见，不构成律师–客户关系，不能替代美国、中国、欧盟或日本执业律师签字。**
> 产品锁定见 [plan.md](./plan.md) §0、§7。

主体假设：出版商 **UseONE, LLC**（美国）；不上国区；获客含小红书。处理在 Cloudflare + Kimi。**结构化日记在 Lantai D1**（字段+短文，无原图）；Notion 为可选镜像。

**商业前提（已锁）：** ICP = 普通用户。订阅靠 App 内快录 + 观察走量。vibe coding 能复刻 Notion 管道，故 Notion/快捷指令不是中心。美/欧/日都卖饮食和精气神。对策：同一二进制、分场景同意、约束发挥。

**v0.12 合规增量：** 平台成为日记 **控制者**（短文与字段），不再能说「档案只在你的 Notion」。原图仍处理即销毁。删账号必须删 `lantai_records`。隐私政策写明存什么、存多久。推送打开 App 不等于减少处理义务。

## 1. 结论

| 范围 | 商店策略 | 条件 |
|---|---|---|
| **M1a 手动** | 全球可做 | 屏 A：TOS/隐私 |
| **饮食视觉** | **美/欧/日/港都做** | 屏 Diet：餐图云端处理、估算非医疗、背景里的人不是分析对象。高危在 **健康宣称 + 餐图里误入的人脸**，不是 BIPA 主战场 |
| **精气神** | **美/欧/日/港都做** | 屏 Jing：书面同意（按 BIPA/GDPR 第 9 条/APPI/PIPL 的**高水位**写一套，全球同一文案）。禁止「美区不做 / 欧区不做 / 日区不做」 |
| **通用填 schema** | **都做** | 看起来最像 OCR，**管道风险与饮食同级**（照片进 Kimi）。若用户提示词或图片主体是脸/掌/证件，风险升到精气神。必须：系统只填字段、禁止人物发挥；主体是人脸则拒写或走精气神同意 |
| 「是本人」勾选 | 合同有效、核身无效 | 挡不住第三人、监管、Apple |
| 人脸核身 / enrollment | **不做** | 会把产品做成身份识别 |
| 按商店关掉精气神 | **不做** | 等于没有订阅爆点 |

律师改的是 **措辞、分级、DPA**，不是「要不要在美欧日卖精气神」。外测前仍要过勾选终稿：有真人脸进队列，风险与正式版同类。

## 1.1 三种视觉：风险不是同一个，管道是同一条

三者都是：用户图 → 压图 → Kimi → 丢像素 → **字段/短文进 D1**（可选再镜像 Notion）。Apple Nutrition Label 对 Photos linked + 第三方处理三者都要勾。D1 短文是个人数据存档，须可删。

差在 **模型被允许发挥什么**，以及 **图的主体是不是人的身体标识**。

| | 通用 schema（约束后） | 饮食 | 精气神 |
|---|---|---|---|
| 意图 | 看见什么填什么（菜名、金额、书名、勾选字段） | 估算份量/热量区间 | 对 **这张脸/这双手** 写气色短文 |
| 发挥 | **禁止**人物传记、健康判断、看相 | 允许食物层估算；禁止诊断/减肥承诺 | 允许一段文化向建议；禁止铁口/医疗/身份 |
| 生物识别法（BIPA 等） | 主体不是脸/掌时 **弱**；主体是脸时 **与精气神同类** | 餐图误入人脸：弱；不要拿人脸算热量 | **主风险** |
| 健康广告法 | 低（除非用户 schema 是病历） | **主风险**（热量） | 中（气色≠诊断，文案必须钉死） |
| 证件/病历/儿童 | 自定义库最容易误传 → **拒识或拒写** | 中 | 高（相册小孩） |
| 订阅叙事 | 有用，爆点弱 | **日活** | **差异化爆点** |

所以：饮食和精气神都高危，但是 **不同的高危**。通用不是「没风险」，是「默认低发挥、一放松就变成精气神」。产品上要把通用锁死在填表，避免第三条路径变成未同意的看相。

## 2. 关键法律事实（产品常会说错的）

**处理即销毁 ≠ 没有处理。** GDPR、CCPA/CPRA、PIPL、BIPA、APPI 管的是 processing / collection。像素进 Kimi 就是处理。销毁只降留存，不降采集义务。

**快捷指令绕不开同意。** 同意记 D1；无对应场景同意则该类 jobs 403。

**第 230 条帮不上。** 自己把图送给模型并生成文字，是自己的处理。

**肖像权人不是合同相对方。** 「这是我」只约束用户。第三人仍可能主张。产品闸降低频率，不是豁免。

**地理开关解决不了欧日。** GDPR 明示同意、日本 APPI 向第三方提供（Kimi 出境）同样要告知+同意。美区关掉精气神、欧日照开，审核和用户预期会裂；三区都关就没有爆点。正确做法： **全球同一功能 + 同意文案取高水位**（BIPA 书面同意的要素覆盖 GDPR/APPI 需要的目的、处理者、销毁）。

## 3. 分法域（功能全开，同意取高水位）

### 3.1 美国

Clickwrap：独立屏、默认不勾、TOS/隐私可点开。饮食 / 精气神 / 通用 **三套场景同意**，禁止「继续即同意全部」。

**BIPA：** 精气神仍是集体诉讼主风险。对策定为 **书面同意面向所有用户**（目的、标识类型、销毁=推理结束立即删除、不出售），而不是屏蔽伊利诺伊、也不是美区下架精气神。伊利诺伊用户看到的和加州用户相同；屏 C 并进精气神流程，不必做不可靠的 IP 定位。listing **不要**写「符合 BIPA」。

**CCPA：** 敏感信息告知；Kimi 当服务提供商禁止训练。

**COPPA：** 勾选年龄是弱证据。分级按 12+ 起，精气神文案按 17+ 准备（律师与审核再降）。

**FTC：** 饮食主战场。估算+区间+非医疗。

### 3.2 欧盟 GDPR

不屏蔽欧区下载。照片=个人数据。精气神按第 9 条 **明示同意** 来写（即使产品不做核身，监管仍可能把脸部分析算进去）。通用/饮食走第 6 条同意+合同，系统提示禁止对人物发挥。内部做 DPIA（律师模板）。处理者合同（Kimi）必做。不要在政策写「不适用 GDPR」。

### 3.3 日本 APPI

日区要做精气神和饮食。向境外 Kimi 提供个人数据：告知目的、提供对象类别、取得同意。脸/掌按个人数据（及可能的敏感信息）处理，**同一套高水位勾选即可**，不要单独做「日区关闭」。商店隐私问卷与实际路径一致。

### 3.4 中国 PIPL

不上国区。小红书获客 → 境内自然人仍可能适用：单独同意、出境告知、可撤回。中文政策必做。不要写「数据不出境」或「不看脸」。

### 3.5 Apple

5.1：Photos linked + 第三方处理（三种视觉都要）。脸/掌 ≠ 指纹。可关精气神（饮食继续）。同意屏与 Nutrition Label 必须一致。

### 3.6 Notion 与 Kimi

政策必须写：**原图默认不进 Lantai；短文与字段在 Lantai。若你连接 Notion，原图/行会进你的 Notion。**

## 4. 用户保证条款能做什么、不能做什么

**能做：** 本人或许可的陈述；禁止给未同意第三人建档；停 `config_id`；不退已耗点（TOS 写清）；合理范围内的用户赔偿；收到通知后停推理并指导删 Notion。

**不能做：** 约束被拍者；预先放弃 BIPA/GDPR 监管责任；「点了同意就不是处理者」；用勾选代替产品闸。

## 5. 分场景同意（产品可做，律师改字）

全部在 App，不可滑过。版本号分场景写入 D1。

**屏 A — 所有人（含仅手动）**  
勾选同意 TOS + 隐私政策。

**屏 Diet — 第一次用饮食模板**（短，不复用精气神）

1. 餐图发送云端一次性识别，用于填我的 Notion 字段（菜名/份量/热量区间）；结束后删图。原图在我的 Notion。  
2. 热量是估算不是医疗，不承诺减肥。  
3. 不要用本功能分析照片里的人；若主体是人脸，服务可以拒绝。

无 Diet 同意 → 饮食 jobs 403。撤回 Diet 不影响精气神，反之亦然。

**屏 Jing — 第一次用精气神**（高水位，全球同一套；含 BIPA 要素，不再按州/国家分叉功能）

1. 目的：一张脸 + 两张掌，云端一次性分析，生成写入 Notion 的短文本；结束后删除照片与中间特征；平台不存原图。原图在我的 Notion。  
2. 可能从图像中读取面部与手掌的可见特征（不是指纹、不是解锁、不是身份核验），不建库、不与他人比对、不出售。  
3. 照片是我本人或已获明示许可（含监护人）；不给未同意的人看气色。  
4. 年龄确认（律师定 13/16/17）。  
5. 文化/自我观察参考，非医疗、非命运铁口。

无 Jing 同意 → 精气神 403。

**屏 Generic — 第一次用自定义视觉模板**

1. 图只用于按我配置的 schema **抽取可见信息填字段**，不做人物点评或看相。  
2. 不上传身份证/护照/医疗记录/他人脸部为主体的照片。  
3. 若系统判断主体是人脸或手掌：拒写，或要求先完成屏 Jing。

系统侧（同意之外）：通用模板的 hidden system prompt 禁止人物传记；classifier 脸/掌为主体 → 不生成发挥性文字。

撤回：设置里分开关 Diet / Jing / Generic。PIPL/GDPR 需要这一层。

## 6. 隐私政策必须出现的句子

- 三种视觉都会把当次照片发给云推理商；处理即销毁；Notion 里由用户保管原图与文字。  
- 精气神：不核身、不建人脸库、不互相比对；掌 ≠ 指纹。  
- 饮食：估算；非医疗。  
- 通用：填 schema；主体为人脸/证件则拒绝或另走精气神同意。  
- 第三方类别：Kimi、Cloudflare、RC、登录、Notion。  
- 通知：本地习惯 + 任务完成推送。  
- 国际传输发生在美国/供应商所在地。  
- 删账号清 D1；Notion 用户自删。

禁止：我们不处理生物识别；我们保证图中的人是账号持有人；数据只留在中国；OCR 不涉及个人信息（假）。

## 7. 风险排序

1. 精气神 × BIPA（用全球书面同意承接，不关功能）  
2. PIPL + 小红书获客出境  
3. 通用模板被用来看相/扫证件（用拒写 + 屏 Generic 降到可控）  
4. 第三人肖像  
5. Apple 5.1 与 Label 不一致  
6. 饮食热量宣称（文案可控）  
7. iCloud 槽位文件被转发（轮换 `config_id`）

## 8. 已锁决策（律师只改措辞）

1. **美/欧/日/港同一套功能**：饮食 + 精气神 + 通用视觉都卖。不做商店级精气神开关。  
2. **分场景协议**（屏 A / Diet / Jing / Generic），不是一份 TOS 打天下。  
3. 精气神同意按 BIPA 书面要素写给 **所有人**（覆盖欧日告知要求）；不靠 IP 屏蔽伊利诺伊。  
4. 通用视觉 = 填表，不是第二条精气神。脸/掌为主体则拒绝或要求 Jing 同意。  
5. 不做人脸 enrollment。  
6. 国区不上；小红书 → 中文政策 + 单独同意必做。  
7. Notion 原图由用户控制；平台只承诺停推理。  
8. 年龄与 12+ / 17+ 分级：律师+审核定，**不定「日区欧区不卖」**。

执业律师交付物：TOS、隐私政策、四屏勾选终稿、Nutrition Label 对照、Kimi DPA、DPIA 草稿（欧区）。
