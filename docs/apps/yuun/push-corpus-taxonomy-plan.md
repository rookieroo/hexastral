# Push corpus taxonomy — 多信号打分层 plan

> **Status**: Proposed (2026-08-17) — **MVP 不上**；待 `auspice_push_opens` 指标
> A/B 数据出来后再排期实施。本文冻结设计，供届时开工。

## 0. 为什么做 / 为什么现在不做

- 现状：钩子 = `relation(日干×日主) × energy(日支×日主)` 二维语料格 + 吉/平/凶三档
  判语，零 LLM、确定性、按天轮换。已满足 MVP（走量 app 的免费钩子需求）。
- 目标：把「定性」从三档判语升级为**多信号打分 → band → 语料 key**，让物料与
  「用户八字 × 当天历法」的组合对应更细致（一对多轮换，非一对一）。
- **为什么不在 MVP 做**：① 内容工程量（≈500 条四语物料）会挤压上架排期；
  ② 推送打开率 A/B 基建（migration 0040）刚落地，没有任何 variant 数据——
  先测出现有 24 变体 + hook 的基线，再决定语料往哪个方向投；
  ③ ADR-0003 红线对新增 band 的命名/语义有约束，需要单独一次内容评审。

## 1. 打分信号（全部确定性，无 LLM）

| 信号 | 数据来源 | 权重（建议） | 说明 |
|---|---|---|---|
| 用神/忌神对齐 | `birthHour/gender` 已在 `auspice_push_subs` → astro-core 完整用神 | 0.35 | 当日五行 = 用神 → 上抬；= 忌神 → 下压 |
| 日干×日主五行关系 | 现有 `relationOf` | 0.25 | 生/克/比和/泄/耗 五关系（现状只有三态） |
| 日支×年支冲合 | `birthBranch` × `dayBranch`（六冲/六合/三合/刑害） | 0.2 | 冲 = 波动日，合 = 顺遂日 |
| 建除/值神 tier | day payload 已有 | 0.1 | 装饰性语态，弱信号 |
| 星宿 tier | 同上 | 0.1 | 同上 |

紫微流日四化/流日命宫 = **P2**（需每设备完整紫微盘；先验证八字维度有效性再加）。

## 2. Band 与语料 key

- 加权分 → **5 band**（命名遵守 ADR-0003，禁 大吉/大凶/必中）：
  上吉 / 顺 / 平 / 缓 / 避。文案姿态 = "适合行动 / 保持节奏 / 留意波动"。
- 语料 key = `band × relation(3) × 场景(2: 行动向/心性向)` = 30 格 × 每格 8 条
  轮换物料 × 4 locale ≈ **480 条**（一次性内容工程）。
- **一对多，不做一对一**：60 甲子循环下一对一必然单调重复；轮换 + 现有
  `last_body_key` 防重复 + 24 变体结构共同保证多样性。
- `hookKey` 升级为 `band:relation:scene:idx`，延续现有 A/B 归因格式。

## 3. 实施顺序（数据驱动）

1. **P0（已在跑）**：MVP 钩子门槛 = 生辰（2026-08-17 已改）。
2. **P1 观察期**：跑 2–4 周，用 `auspice_push_opens` 看：有生辰 vs 无生辰的
   打开率差、现有 hook variant 表现、en hook 路径 vs CJK 干支路径。
3. **P2 打分实现**：`personalAlmanacOverlay` 升级为多信号打分（纯引擎，可先于
   语料落地，band 输出灰盒观察）。
4. **P3 语料扩充**：按 P1 数据选定 band 粒度与场景切分，一次性补四语物料
   （内容评审一次过 ADR-0003 词表）。
5. **P4 紫微维度**：数据支持时再加（每设备紫微盘 + 四化语料，内容量另估）。

## 4. 验收

- band 判定 golden tests（astro-core 侧确定性）；
- 打开率 A/B：新 band 语料 ≥ 基线 variant 打开率，否则回滚保留旧语料；
- 全量物料过 `portfolio-voice` hard forbidden 词表检查。
